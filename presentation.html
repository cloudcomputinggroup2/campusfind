Project Overview

Executive Summary & Vision

Bridging the campus lost-and-found communication gap with cloud infrastructure

Slide 2 / 20
🏫 The Campus Problem

University students lose valuable items daily—IDs, keys, laptops, chargers, textbooks. Recovery is slow, disorganized, and stressful.

  • Fragmented WhatsApp / Telegram chats
  • Unindexed bulletin boards
  • Zero real-time search or verification
💡 The Solution

CampusFind: A centralized, responsive web platform backed by scalable AWS cloud infrastructure.

  • Instant keyword & category search
  • S3-backed image verification
  • Printable flyers with tear-off contact slips
  • Lifecycle status tracking
☁️ AWS Cloud Strategy

100% compliant with AWS Free Tier while adhering to enterprise cloud best practices.

  • EC2 (Ubuntu 24.04): Nginx + Gunicorn
  • RDS (PostgreSQL): 3NF Relational DB
  • S3: Isolated object media storage
  • CloudWatch: Telemetry & monitoring
Problem Statement

Traditional Friction vs Cloud-First Solution

Why physical boards and chat groups fail on modern university campuses

Slide 3 / 20
❌ Traditional Methods (Failures)
  • Scattered Channels: Inquiries scattered across WhatsApp, Reddit, Facebook, Instagram, and physical paper notes.
  • Zero Search Capabilities: No ability to filter by campus building, date range, item category, or keywords.
  • Lingering / Obsolete Records: Notice boards and chats are never cleaned up after an item is found.
  • Privacy & Safety Risks: Students broadcast personal phone numbers publicly to open groups.
✅ CampusFind Cloud Paradigm
  • Single Source of Truth: One unified university portal for all lost, found, and reunited property.
  • Multi-Parameter Indexing: Real-time filtering by status, building presets, category, and date.
  • Verified Lifecycle Management: One-click "Mark as Claimed/Reunited" updates the catalog immediately.
  • Security & Access Control: Salted password authentication, CSRF/XSS protection, and scoped contact sharing.

Cloud Infrastructure

AWS Multi-Tier Cloud Architecture

Production-ready VPC architecture built entirely within AWS Free Tier limits

Slide 10 / 20
☁️ Architectural Highlights
  • Region: us-east-1 (N. Virginia).
  • Web/App Layer (Public Subnet): EC2 (Ubuntu 24.04, t2.micro) running Nginx reverse proxy + Gunicorn WSGI.
  • Database Layer (Private Subnet): Amazon RDS PostgreSQL instance strictly accessible only from EC2 SG.
  • Object Media Storage: Amazon S3 bucket for photos with least-privilege IAM policy.
  • Observability: Amazon CloudWatch telemetry tracking EC2 CPU and network load.
Compute Tier

Amazon EC2, Nginx & Gunicorn WSGI

High-performance reverse proxy and daemonized application server

Slide 11 / 20
⚙️ Server Configuration
  • Amazon EC2 Instance: Ubuntu Server 24.04 LTS, t2.micro (1 vCPU, 1 GiB RAM).
  • Nginx 1.24+: Reverse proxy on port 80/443 with Gzip compression and static asset caching.
  • Gunicorn 21+: WSGI worker process listening on Unix socket / port 8000.
  • Systemd Daemon (gunicorn.service): Auto-restart on failure and server reboot.
  • Static Assets: Compressed via WhiteNoise storage backend.

Database Tier

Amazon RDS PostgreSQL & 3NF Schema

Managed relational persistence, third normal form normalization, and DB isolation

Slide 12 / 20
🗄️ RDS Architecture & Schema
  • Engine: Amazon RDS PostgreSQL 16 (Free Tier db.t3.micro).
  • Private Subnet Security: CampusFind-RDS-SG permits inbound traffic on port 5432 strictly from CampusFind-EC2-SG.
  • Data Normalization (3NF): Clean separation between auth_user and core_item with cascading integrity.
  • Query Indexing: Performance B-tree indexes placed on status, category, and created_at.
  • Automated Seeding: seed_data.py generates test accounts and realistic campus records.
Storage Architecture

Decoupled Media Storage with Amazon S3

Isolating ephemeral compute disk from persistent image assets

Slide 13 / 20
📦 Amazon S3 Integration
  • Dedicated Bucket: campusfind-item-images-capstone in us-east-1.
  • Stateless Compute: EC2 instances can be destroyed, scaled, or replaced without risking user uploaded photos.
  • Direct Integration: Powered by django-storages and AWS Python SDK (boto3).
  • Offline Fallback: If USE_S3=False, Django gracefully stores media in local directory for zero-config local development.
⚡ Upload Validation Pipeline
  • MIME & Format Whitelist: Only valid image types permitted (.jpg, .jpeg, .png, .webp, .gif).
  • File Size Ceiling: Strict 5MB limit enforced both client-side (JS) and server-side (Django Form).
  • Secure Filename Hashing: Random UUID/timestamp prefix prevents path traversal attacks and collisions.
Cloud Security

IAM Least-Privilege & Application Hardening

Multi-layered defense across credentials, identity, framework, and network layers

Slide 14 / 20
🛡️ Application Security Defenses
  • Zero Hardcoded Secrets: Database hosts, API keys, and Django SECRET_KEY injected at runtime via .env.
  • Cryptographic Password Hashing: PBKDF2 algorithm with SHA-256 and unique cryptographic salt per account.
  • Injection Immunity: Parameterized Django ORM queries completely neutralize SQL injection risks.
  • Cross-Site Mitigation: Strict CSRF tokens on all forms and auto-escaped HTML against XSS.

Engineering Reflections

Technical Challenges Encountered & Solutions

Key engineering problem-solving during the 3-day cloud development lifecycle

Slide 17 / 20
⚠️ WhiteNoise Test Manifest

Challenge: Strict static file hashing caused ValueError in automated test runs when assets weren't pre-collected.

Solution: Switched to CompressedStaticFilesStorage to retain high Gzip compression while eliminating test failures.

🔌 Offline Local Development

Challenge: Enabling team members to develop and run tests offline without active AWS IAM credentials.

Solution: Engineered conditional storage backend in settings.py switching automatically between local disk and S3 via USE_S3.

🔒 RDS Subnet Isolation

Challenge: Securing the database from public brute-force scans while allowing seamless EC2 migrations.

Solution: Placed RDS in a private DB subnet group and configured CampusFind-RDS-SG to accept port 5432 only from CampusFind-EC2-SG.
